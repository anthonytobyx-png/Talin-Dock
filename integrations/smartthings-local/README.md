# Authenticated SmartThings TV LAN route

This household integration runs inside the TV's existing Edge hub. The hosted Talin browser connects directly to the private HTTPS listener using an installed client identity. The PC is used for commissioning only. Native owner-managed SmartThings Rules translate on/off request events into the real TV's switch commands and mirror SmartThings-reported state. Those rules currently report executionLocation Cloud, so internet is required. No third-party OAuth client, official CLI token copied into Talin, paid API, Alexa, external bridge or port forwarding is used.

## Verified household result

Mutual TLS with the household CA accepted the matching identity and rejected missing, untrusted-signature and server-purpose client certificates. A real On request through this endpoint produced On in a separate official provider read. A 60-second hub timer produced On with the requesting process closed; Off was then requested and the starting Off state restored. Timer cancellation and saved history across driver updates were verified. The HTTPS endpoint remained reachable while SmartThings reported TV Off. These provider readings do not establish independent physical observation or physical iPad/PC-shutdown acceptance.

The owner completed iPad identity/root enrollment and physically confirmed on/off. On 6 November, eleven remote actions were also physically confirmed through the authenticated hub route: Up, Down, Left, Right, OK, Back, Home, volume up/down and mute/unmute. OK was tested on the identified Discover tab. The TV was returned to its starting Off state. SmartThings' audio-volume report remained unchanged during successful physical tests, so the remote exposes relative commands and separate mute/unmute buttons, without inventing a current volume or mute state. Source selection reports no available inputs and stays absent.

The same controller is available in Remote and the Samsung device dialog. While that panel is visible it reads authenticated hub status every three seconds, so delayed power reports update key availability without replaying the power command. Only the authenticated hub's allowlisted remote catalog is displayed; remote keys require reported power On and a reachable hub. Hub acceptance is not appliance execution. The UI labels the last SmartThings report, its receipt time and the absence of an underlying TV sample timestamp. It never invents source/app identifiers or online TV status.

## Security and deployment

Public source contains no private keys. The instance-only src/local_config.lua must be assembled in the owner's protected commissioning directory, never this checkout, and contains only the server key/certificate and public CA. It is excluded by gitignore. CA signing and client private keys are not uploaded to Samsung. The public root certificate may be distributed by Talin; it is not a credential.

The household root includes IP name constraints for 192.168.1.3/32 and DNS constraints limited to reserved .invalid names. Current server/client certificates expire 7 December 2027. Renewal and revocation require replacing the relevant identity/CA and private driver configuration. No trust-store change or debugger-certificate exception is automated. Owners must review and install/trust the public root and password-encrypted client identity on each authorised browser device. Keys belong in the OS keychain, never browser storage. Only the non-sensitive endpoint address is stored locally.

POST requires exact Origin https://talin-dock.pages.dev and text/plain JSON with a bounded body. This avoids credential-free CORS preflight on older Safari while retaining origin validation and mandatory mutual TLS. GET responses grant CORS to Talin only. Header/body limits, timeouts and four concurrent client slots bound resource use. State-changing requests reserve idempotency IDs before publishing; uncertain requests are not automatically replayed. There are no arbitrary destination or device-ID parameters.

Timers are persisted as immutable JSON strings because the hub datastore wraps table values. Startup re-arms pending timers; claimed/uncertain actions are not retried and timers overdue by more than two minutes expire. Recent flash writes can be lost after abrupt power failure. Ten pending timers and 64 recent records are allowed. A sent timer means published to SmartThings, not physical confirmation.

The package replaces the earlier diagnostic packageKey for this existing household hub; do not install it blindly on another household. Use its own generated capability namespace, actual verified TV and LAN-device IDs, and owner-only channel. Five native rules handle power requests, switch-state mirroring and status. Eleven additional rules match exact remote-* values on the existing bounded diagnostic stage attribute and send fixed Samsung remoteControl key/state arguments or standard audioVolume/audioMute commands to the actual TV. No device identifier or key name is accepted from the browser. The stage attribute remains a routing diagnostic; request refresh to republish the listening port before reading it for maintenance. All sixteen rules execute in Samsung Cloud. Instance rule JSON/IDs and CLI credentials stay outside the repository.

## Maintenance limits and acceptance

Samsung only supports port 0 binding for Edge server sockets. The listener port changes after a hub/driver restart. Request refresh on the Talin hub connection test device, then read local-tls:PORT:ready and update TV connection setup in Talin. Current verified endpoint is https://192.168.1.3:38293. A reviewed web release may update its known default: if a saved endpoint fails, the app tries that default once with authenticated read-only GET, adopts it only after valid status, and never replays commands or scans ports. Unexpected future restarts can still require maintenance. A TV IP change requires an updated scoped server certificate, CSP allowlist and endpoint. No unsupported port-binding bypass is attempted.

The owner completed iPad certificate import/trust and confirmed power and the remote actions above. A physical PC-shutdown test, background-timer observation and cold offline reopening remain acceptance checks. If Safari cannot authenticate, controls remain disabled; do not bypass certificate errors. The one-time commissioning helper served only a strongly password-encrypted PKCS#12 identity for 30 minutes, displayed its DPAPI-protected password only over loopback on the PC, logged no requests, and exposed no appliance controls. It is stopped; both temporary firewall rules are removed and the original Python inbound block restored. It is not a runtime dependency.

Run test.lua with Fengari (30 boundary/idempotency/timer/remote checks). App tests cover endpoint validation, malformed remote catalogs, port recovery, stale/offline controls and separation of hub acknowledgement from TV state. Real TLS negative tests, physical owner observations and provider checks are separate from mocks.

## Household onboarding policy

Setup is consolidated in Settings. Provider consent is not repeated per widget. The owner completed one-time enrollment on the iPad after the web connections were prepared. Existing OS identity authentication remains required for this LAN route; cloud sign-out alone does not revoke that identity. Additional browser devices need their own enrollment. No remote iPad approval, publicly trusted LAN hostname, access from arbitrary external networks or universal device compatibility has been established. Never weaken authentication or certificate verification to hide these limits.
